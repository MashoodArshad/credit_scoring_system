# Model Card — Credit Scoring System

*Following the Model Cards framework (Mitchell et al., 2019).*

---

## 1. Model Details

| Field | Value |
|---|---|
| **Model type** | Logistic Regression (L2-regularized, `class_weight='balanced'`) |
| **Version** | 1.0.0 |
| **Hyperparameters** | `C ≈ 0.216`, `penalty=l2`, `solver=lbfgs`, `max_iter=3000` |
| **Input** | 21 raw applicant features → 11 engineered → **26 selected** |
| **Output** | `P(creditworthy)`, approve/reject decision, risk tier, reason codes |
| **Decision threshold** | 0.64 (validation cost-optimal) / 0.52 (test) |
| **Artifact** | `models/credit_scoring_logreg_v1.joblib` (+ `.meta.json`) |
| **Pipeline** | `FeatureEngineer → Preprocess → PositionSelector → LogisticRegression` |

## 2. Intended Use

- **Primary:** automated **pre-screening** of consumer credit applications to rank
  applicants by predicted default risk and produce approve/reject recommendations.
- **Out of scope:** sole, unreviewed decisioning for high-value loans; use outside
  consumer credit; pricing beyond the calibrated probability's reliability.
- **Users:** credit-risk analysts and underwriting teams. Final adverse-action
  decisions should include human review and the generated reason codes.

## 3. Factors / Segments

- Evaluated across the full population and by **protected attributes**
  (`gender`, `marital_status`) for fairness auditing — these are **excluded from
  training** and used only to detect disparate impact.
- Performance reported overall (validation + test). Per-segment fairness metrics
  (AIR, equal-opportunity difference) are flagged as future work.

| Approved-portfolio bad rate | ~2.2% | — |

**Business cost** = `5·FP + 1·FN` (FP = approving a defaulter). Threshold tuned to
minimize this cost.

## 5. Training & Evaluation Data

- **Source:** realistic **synthetic** financial dataset (10,000 applicants; see
  `README.md § Dataset`), generated by a noisy data-generating process with
  injected quality issues.
- **Split:** stratified **64 / 16 / 20** (train / validation / test), seed-pinned
  and verified reproducible.
- **Prevention:** preprocessing and feature selection fit on **train only**;
  test set evaluated **once** at finalization.

## 6. Quantitative Analyses

- **10-algorithm comparison:** Logistic Regression led (AUC 0.943), with Gradient
  Boosting / RF / XGBoost close behind (0.92–0.94).
- **Tuning:** LogReg unchanged by tuning (already near-optimal); XGBoost improved
  from AUC 0.918 → 0.935; early stopping selected 449/2000 rounds.
- **Generalization:** test AUC (0.9438) ≥ validation (0.9425) → no overfitting.
- See `reports/` for the full evaluation, tuning, and explainability reports.

## 7. Ethical Considerations & Fairness

- **Protected attributes** are excluded from model inputs; retained only for audit.
- **Interpretability:** per-applicant reason codes support adverse-action notices.
- **Privacy:** no real PII (synthetic data); design separates identifiers/protected
  attributes from features.
- **Bias monitoring is basic** — full disparate-impact reporting is a future
  improvement; deploy with a fairness review.

## 8. Caveats & Recommendations

- Coefficients can be distorted by **multicollinearity** → use SHAP/permutation
  for global importance, and VIF-prune for production reason codes.
- **Synthetic data** favors linear models; re-validate on real data before use.
- Probabilities are **moderately** calibrated; apply isotonic/Platt recalibration
  if used for risk-based pricing.
- `interest_rate` is partly **endogenous** (risk-based pricing) — interpret with care.
- Monitor for **concept drift** (PSI) and retrain on a schedule.
